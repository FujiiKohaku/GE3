# オブジェクト別フォグ設定 実装計画書

作成日：2026-10-14  
状態：半透明の初回対応と、不透明Object3dへの対応を実装済み。最新の結果は第12節を参照。

## 1. 目的

使う側から `SetFogEnabled(false)` を指定し、敵弾をフォグの影響から除外できるようにする。
背景の霧を維持し、地形・ボスとの奥行き判定と半透明同士の重なりを扱う。

フィアーボスの弾が見えない原因は、まだ実画面で確定していない。実装前にフォグON/OFFの比較を行い、描画順の変更が必要か確認する。

## 2. 初回の対応範囲

- `Object3d` で描画する半透明物体に、個別のフォグON/OFFを実装する。
- `BaseBullet` からも同じ設定を呼べるようにする。
- フィアーボスの通常弾・チャージ弾を最初の適用対象とする。
- フォグONが既定値。OFFにした物体にも地形との深度テストは適用する。
- 不透明物体のフォグOFF、追尾弾の透明化、パーティクルの全面的な描画方式変更は初回に含めない。

追尾弾は通常弾と別の描画設定である。同じ問題だと決めつけず、個別に確認する。
通常弾クラスは他の敵も利用するため、フィアーボスだけに適用する段階ではボスの生成箇所でOFFにする。

## 3. 現状と問題点

現在の主要な順序：

1. 3D描画：背景・地形・自機・敵・敵弾・ボス。
2. 影・間接光・反射などの処理。
3. ボリュームの霧や距離フォグの合成。
4. DLSSなどの画像処理。
5. パーティクル。
6. 残りのポストエフェクトと最終出力。
7. UI。

通常敵弾は半透明で、深度を書き込まない。距離フォグは画面の深度から濃さを計算する。
そのため、弾が手前にあっても背景の深度に基づくフォグが合成される可能性がある。
設定フラグを追加するだけでは、画面全体に後からかかるフォグを避けられない。

## 4. 公開API

```cpp
// 初回は対応する半透明物体で使用する。
object->SetFogEnabled(false);
bullet->SetFogEnabled(false);
```

- `Object3d` に設定と取得用APIを追加する。
- 弾では初期化前に指定しても保持され、内部の `Object3d` 作成時に反映されるようにする。
- 不透明物体や未対応のシェーダーにOFFが指定された場合、開発ビルドで理由を表示する。効いたように見える無言の無処理にはしない。
- フォグOFFは、ライティング・影・当たり判定をOFFにする意味ではない。
- ステージ全体のフォグがOFFなら、個別設定がONの弾にもフォグをかけない。

## 5. 描画処理の設計

### 5.1 半透明描画を管理する

`Object3d::Draw()` で対応する半透明物体を描画要求として登録し、エンジンが専用の段階で描く。
フォグON/OFFの違いで別々に並べ替えず、同じ半透明グループとして奥から手前へ並べる。

- 描画の登録と実際のGPU描画を分離し、キュー実行時の再登録を防ぐ。
- 画面描画用のキューだけを変更し、影・レイトレーシング用の描画経路を混同しない。
- カメラの前方向に沿った奥行きを基準に、安定した順序で並べる。
- 描画対象の寿命を保証し、キューはフレーム開始・終了とシーン切り替え時に整理する。

オブジェクト単位の並べ替えだけでは、交差する半透明形状を完全には解決できない。
必要な箇所では既存の部品順序や描画優先度を保ち、対象場面で重なりを検証する。

### 5.2 背景フォグと半透明フォグを分ける

不透明な背景には現在の画面全体のフォグを使う。
後から合成する半透明物体には、物体自身の位置からフォグを計算して適用する。

- ON：弾自身の位置からフォグを計算する。
- OFF：弾の色にはフォグを適用しない。
- 背景は、半透明の弾越しにもフォグがかかった状態で見える。
- フォグの二重適用を防ぐ。
- 通常のアルファ合成と加算合成では、霧の合成方法を区別する。

既存の `Fog.hlsli` とパーティクル用のフォグ処理を参照する。
ただし、それだけでボリュームの霧まで同等に再現できるとは限らない。
OFFは距離フォグとボリュームの霧の両方から除外し、ONで対応する霧の種類も明記する。
ON側の見た目を維持できない場合は、未対応状態で全半透明物体を新経路に移さない。

### 5.3 奥行きと描画先を維持する

専用の半透明描画段階では、適切な背景深度を参照して深度テストを行う。
通常弾は現在と同じく深度を書き込まない。

既存の3Dパイプラインは複数の描画先を使い、パーティクル合成側は別の描画先を使う。
そのため、敵弾の呼び出しだけをパーティクル描画位置へ移す方法は採用しない。
描画先の数・形式に一致するパイプラインと、必要なシェーダー入力を用意する。

DLSS使用時は、描画先の解像度・背景深度の解像度・カメラのジッターを一致させる。
初回はDLSS後の合成段階を候補とし、敵弾のちらつき・輪郭・遮蔽を検証して確定する。
この場合、弾はDLSSの入力には含まれなくなるため、移動時の画質変化を確認する。

### 5.4 既存の特殊描画を確認する

クラゲボスは半透明部品を持ち、深度書き込みと独自の部品並べ替えを使用している。
通常弾と同じ設定へ一律に変更しない。

移行前に、各半透明物体について以下を一覧化する。

- 使用シェーダー・合成方式・深度書き込み。
- 独自の並べ替えと描画先。
- 反射・影・モーションベクトルへの寄与。
- パーティクルとの前後関係。

深度を書く半透明物体を既存経路に残す場合は、後から描く弾との遮蔽や、半透明越しの表示への影響を記録する。
パーティクルとObject3dの間に一律の前後関係を設けるだけで問題が出る場合、描画グループや共通の並べ替えが必要になる。
重なりの検証が終わるまで、汎用的な個別フォグ対応が完成したとは扱わない。

## 6. 実装手順

1. **原因の切り分け**：通常弾・チャージ弾・追尾弾を区別し、フォグON/OFFの同条件の画面を比較する。弾のサイズ・透明度・深度判定も確認する。
2. **半透明描画の調査**：既存の利用箇所、特殊な深度書き込み、パーティクルとの重なりを整理して移行範囲を決める。
3. **APIと描画キュー**：個別設定、弾への委譲、描画要求の収集と実行を追加する。既定ONで既存挙動を保つ。
4. **合成用パイプライン**：描画先に合うPSO、背景深度、カメラ情報を接続する。DLSSなし・ありの両方で確認する。
5. **半透明用フォグ**：弾自身の位置で計算するON経路と、OFF経路を実装する。対応シェーダーと霧の種類を明確にする。
6. **フィアーボスへの適用**：通常弾・チャージ弾の生成箇所でOFFを指定する。他の敵弾は既定設定を維持する。
7. **回帰確認**：クラゲボス・地形・パーティクルとの重なり、影・反射・DLSS・画面切り替えを確認する。

## 8. 完了条件

- フォグのある背景でも、フィアーボスの対象弾を発射から接近まで確認できる。
- 地形・不透明なボスの裏の弾は見えず、手前の弾は見える。
- 半透明同士の前後を入れ替えても、対象場面で描画順が不自然に反転しない。
- OFFの弾越しに見える背景のフォグが消えない。
- ONの弾には背景距離ではなく、自身の位置に応じたフォグがかかる。
- ステージ全体でフォグをOFFにした場合、個別ONの弾も霧なしになる。
- 初期化前の設定、シーン切り替え、ポーズ中でも設定とキューが正しく扱われる。
- DLSSなし・あり、対応する画面解像度で弾の位置と遮蔽が一致する。
- Debug／Releaseビルドとシェーダーコンパイルに成功する。
- APIの初期値・設定保持・並べ替え・フレーム間のキュー破棄は必要なテストで確認し、描画結果は画像比較で確認する。

## 9. 次段階：不透明物体の個別OFF

不透明物体には、最前面の表面がフォグを受けるかを記録するマスクを追加し、画面全体のフォグ合成で参照する方式を検討する。
このマスクは距離フォグだけでなく、ボリュームの霧の合成にも接続する必要がある。

背景深度とマスクの解像度・DLSSでの扱い・物体の輪郭を検証する。
半透明は複数の層が混ざるため、不透明用マスクをそのまま流用しない。

## 10. 規模と進め方

小さなフラグ追加ではなく、エンジンの描画経路に関わる中規模以上の変更。
API追加より、既存の半透明描画との統合と画像検証が主な作業になる。
現時点では正確な工数は出さず、原因の比較確認と半透明利用箇所の調査後に見積もる。

各段階でビルドと対象画面の比較を行い、不透明物の対応まで一度に広げない。

## 11. 初回実装の結果

- `Object3d` と `BaseBullet` に `SetFogEnabled(bool)` / `IsFogEnabled()` を追加。初期値はON。
- 弾は初期化前の設定を保持し、内部のObject3dへ反映する。
- 深度を書かない `DanmakuBullet` / `Unlit` マテリアルは、共通キューで奥から手前へ並べ、フォグと画像復元後に描画する。
- ONの物体では、自身の位置まで立体霧を積分した後に距離フォグを適用する。OFFの物体では両方を省略する。背景の霧とアルファ合成は維持する。
- フィアーボスの通常・方向指定・チャージ弾にOFFを指定した。追尾弾の方式は変更していない。
- 発光弾シェーダーがライティング設定に上書きされる設定順も修正した。
- ネイティブ解像度のDLAAでも、合成用深度から投影ジッターを取り除くようにした。

### 確認済み

- シェーダー全523本のコンパイル、Debug / Releaseのゲーム本体ビルド。
- `TransparentDrawQueueTests.cpp`：遠近順、等距離の安定順序、フォグ設定混在、重複、無効な深度、対象破棄、フレーム間のクリア。
- `ObjectFogVerificationScene.h`：初期値、初期化前の設定保持、距離フォグON/OFF、立体霧ON/OFF、地形による遮蔽、混在した半透明の合成。
- 同条件で描画要求の順番を逆にした画像は、比較した9,380箇所すべて一致。
- 960×540のTAA合成と1280×720のDLAA合成で、位置と遮蔽を確認。
- 専用検証の正常終了と、記録対象のDirectX警告・エラーがないことを確認。

再実行：Debug実行ファイルへ `--verify-object-fog` を渡す。5つの条件を順に描画し、PNGを保存して自動終了する。
検証画像は `generated/verification/object-fog/` に保存した。

### 初回実装時の制限・未確認（不透明物は第12節で対応）

- 個別OFFの対応は、深度を書かない半透明のDanmakuBullet / Unlitに限定。不透明物・クラゲボスの深度を書く特殊半透明・その他のマテリアルは未対応。未対応経路のOFFは警告を出す。
- クラゲボスは既存の描画方式を維持。クラゲ越しに見える弾の挙動を含む、実際のボス戦での回帰確認は未実施。
- フィアーボス戦そのものの撮影確認は未実施。同じ通常弾クラスを使う専用シーンで描画を検証した。
- パーティクルは新しいObject3d半透明段階の後に描く。両者を一つの奥行き順に統合する処理は未実装。
- 立体霧ONの半透明物体は、その場で積分するため背景側の時間方向フィルターとは異なる。動く局所光などの見た目とGPU負荷は、実際のステージで追加評価が必要。
- 半透明物体はDLSS/DLAAの入力に含まれない。動く弾の輪郭品質の実戦評価は未実施。

今回の実装は敵弾用の最初の対応であり、全マテリアル・全半透明物体への汎用対応が完了したものではない。

## 12. 不透明Object3dへの対応

### 使い方

```cpp
object->SetFogEnabled(false); // 不透明Object3dもフォグを受けない。
object->SetFogEnabled(true);  // 通常のフォグ適用へ戻す。既定値はtrue。
```

### 実装方式

- 通常の3D描画で不透明Object3dの描画要求を記録する。
- 画面の深度が確定した後、専用のR8マスクへフォグ設定を描く。
- マスク描画は深度EQUAL・深度書き込みOFF。奥にある物体の設定を手前に漏らさない。
- 同じ深度の物体は元の描画要求順で記録する。通常の描画先8枚や影・反射の出力は増やさない。
- 元の頂点シェーダーと変換行列を使い、UV変換と通常のアルファカットアウトをマスク描画でも考慮する。
- マスクは毎フレームONでクリアする。不透明物にOFF指定がないフレームは、マスクへの物体再描画を省略する。
- 距離フォグ・立体霧の合成・画面上の大気散乱が、このマスクを参照する。SSAOや物体の照明は除外しない。
- マスクはDLSS/DLAAより前の、背景深度と同じ解像度・投影ジッターで作る。半透明は従来どおり個別のフォグ設定を使う。
- 解像度変更時にマスクを再作成し、描画要求はフレーム開始・対象の破棄・マスク描画完了時に整理する。

### 確認結果

- 全524シェーダーのコンパイル、Debug / Releaseのゲーム本体ビルドに成功。
- 専用シーンは正常終了し、記録対象のDirectX警告・エラーはなし。
- 不透明ON/OFF、半透明との混在、別の物体に隠れたOFF物体、描画要求順の反転を画像確認。
- 描画要求順の反転前後で、比較した9,380箇所すべて一致。
- 960×540のTAAと1280×720のDLAAで、フォグ除外と遮蔽を確認。
- 距離フォグのみ／立体霧と大気散乱を併用の両方で、OFFの不透明物体のサンプルRGBは `(93,227,125)` を維持。
- 霧が有効なままOFFをONに戻すと、左右とも `(102,181,169)` になり、除外が残らないことを確認。
- ステージ全体の霧をOFFにすると、左右とも `(94,227,125)` になった。

再実行はDebug実行ファイルへ `--verify-object-fog` を指定する。現在は7条件のPNGを保存して自動終了する。
今回の検証画像は `generated/verification/object-fog/opaque/` に保存した。

### 対応範囲と残る制限

- 不透明側の対象はObject3d経路。別クラスのSkinningObject3dや、独自の描画経路を持つ水面等には個別APIを追加していない。
- 深度を書く特殊半透明は引き続き未対応。半透明側の対応マテリアルはDanmakuBullet / Unlit。
- OFFの不透明物がある場合は、可視面を正しく記録するためのマスク描画パスが追加される。大規模ステージでの負荷測定は未実施。
- アルファカットアウトを考慮するコードは実装したが、今回のGPU画像検証はソリッドな立方体を使用。カットアウト形状の専用画像確認は未実施。
- 実際の各ボス戦での回帰確認は未実施。
