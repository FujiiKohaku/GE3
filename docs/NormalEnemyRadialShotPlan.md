# NormalEnemy 放射状射撃 実装計画書

作成日：2026-10-13
状態：2026-10-13、ユーザーの実装許可を受けてコード変更済み。検証結果は末尾に記載。

## 1. 目的と初期仕様案

NormalEnemy の単発射撃を、同じ発射位置から複数の弾が放射状に広がる射撃へ変更する。

この計画では、プレイヤーへの照準方向を軸にした「中央1発＋周囲8発」を初期案とする。周囲の弾は照準軸の周りに45度間隔で配置し、それぞれ照準軸から15度外側へ進む。プレイヤー側から見ると中央の弾と、その周囲に広がる円形の弾列になる。

敵を中心に平面上の全方向へ360度撃つ方式も考えられるが、この計画の初期案はプレイヤー方向へ広がる円錐状の射撃とする。9発という弾数と15度という拡散角は調整用の提案値であり、依頼で指定された値ではない。

| 項目 | 初期案 |
|---|---|
| 1回の弾数 | 中央1発＋周囲8発、合計9発 |
| 周囲の配置間隔 | 照準軸の周りに45度 |
| 拡散角 | 照準軸から15度 |
| 発射位置 | 敵の現在位置、全弾共通 |
| 照準 | 現在のプレイヤー移動予測を維持 |
| 弾速 | 追加指定により0.48へ変更（元の0.8から40％減速）。60FPS換算で28.8ワールド単位/秒。装甲敵は0.8を維持 |
| 発射間隔 | 追加指定により120攻撃カウントへ変更（発射頻度50％減）。60FPS換算で約2秒。装甲敵は60を維持 |
| 発射条件 | プレイヤー前方、距離170以内という条件を維持 |
| 弾の外観・ダメージ・衝突半径・寿命 | 既存の NormalEnemyBullet を利用 |
| 発射音 | 1回の射撃につき1回 |
| 対象 | NormalEnemy。ArmoredEnemy は現在の単発射撃を維持 |

発射間隔は現在フレーム単位で進む。弾の移動と寿命は経過時間を使うため、30/60/120FPSでは射撃頻度が異なる。この変更では発射タイマーの秒単位化を含めず、既存の挙動として確認する。

## 2. 現在の実装と影響範囲

- `project/App/Game/Enemy/Types/NormalEnemy.cpp` の `FireBullet` が、予測したプレイヤー位置へ通常弾を1発生成する。
- `project/App/Game/Enemy/Types/NormalEnemy.h` が発射間隔と弾速を保持している。
- `project/App/Game/Enemy/Types/ArmoredEnemy.cpp` は NormalEnemy の初期化を呼び、射撃処理も継承している。そのまま変更すると装甲敵も複数発射になる。
- `project/App/Game/Enemy/BaseEnemy.cpp` の `AddEnemyBullet` は、弾管理への登録ごとに `EnemyShot` を再生する。9発をそのまま登録すると音も9回再生される。
- `project/App/Game/Enemy/Bullet/EnemyBulletManager.h` が全敵の弾を所有し、更新・描画・寿命切れの除去・プレイヤー後方120単位での除去を行う。
- `project/App/Game/Enemy/Bullet/NormalEnemyBullet.cpp` は寿命20秒、衝突半径1.5、モデルの拡大率0.3を設定する。
- `project/App/Game/Collision/GameplayCollisionSystem.cpp` は敵弾ごとにプレイヤーとのスイープ判定を行う。弾数増加に伴って判定回数も増える。

MoveEnemy とボスは独自の発射処理を持つ。共通の弾クラス自体に放射機能を追加せず、NormalEnemy の生成方向だけを変更する。

## 3. 実行コストの見積もり（実装前の説明）

以下はコードから求めた概算で、実測値ではない。

| 処理 | 現在 | 初期案 | 影響 |
|---|---|---|---|
| 1回の射撃での弾生成 | 1個 | 9個 | 弾と Object3d の生成・初期化が9組になる |
| 照準位置の予測 | 1回 | 1回 | 全弾で共有する |
| 発射方向の計算 | 1方向 | 9方向 | 基底計算と周囲8方向の三角関数・ベクトル演算を追加 |
| 生存弾の更新・衝突判定 | 弾数に比例 | 弾数に比例 | 同じ滞在時間なら通常敵由来の処理は概ね9倍 |
| 描画・描画提出 | 弾数に比例 | 弾数に比例 | 弾数に応じて増加。GPU時間は実測が必要 |
| 発射音 | 1回 | 1回 | 重複再生を抑える |

生存弾数の目安は「射撃中の通常敵数 × 秒あたり射撃回数 × 平均生存秒数 × 1回の弾数」。60FPSで条件を満たし続ける場合は約1回/秒となる。

例：通常敵10体、平均生存時間3秒なら、通常敵由来の生存弾は約30発から約270発へ増える。寿命20秒まで全弾が残る仮定では約200発から約1,800発となる。実際は被弾や後方除去で減り、他の敵の弾も加わる。周囲弾は斜めに進むため、従来と平均生存時間が一致するとは限らない。

ゲーム全体の負荷が9倍になるという意味ではない。増えるのは主に通常敵由来の弾処理である。正確なメモリ量、CPU/GPU時間、FPSへの影響は、実装後の同一条件で測定する。初期実装でプール化や全敵弾の管理方式変更は行わず、測定で問題が確認された場合に追加案を作る。

## 4. 実装手順

### 4.1 通常敵と装甲敵の射撃方式を分ける

NormalEnemy に `isRadialShotEnabled_` と `SetRadialShotEnabled` を追加する。通常敵の初期化では放射状射撃を有効にし、ArmoredEnemy の初期化では親の初期化後に無効にする。

無効時は現在の中央1発だけを生成する。この分岐により、装甲敵の照準・弾速・射撃頻度も維持する。

### 4.2 発射音を射撃単位で再生する

BaseEnemy の `AddEnemyBullet` に、既定値が true の引数 `shouldPlayShotSound` を追加する。弾の登録は毎回行い、音の再生だけをこの引数で制御する。

NormalEnemy は中央弾の登録時だけ true、周囲弾の登録時は false を渡す。既存の他の呼び出しは引数省略によって現在の音の挙動を保つ。音を弾管理の外から無条件に再生せず、現在と同様に管理先がある場合だけ再生する。

### 4.3 共通の照準方向を求める

現在の先読み率0.65による移動予測を1回だけ計算し、敵から予測位置への方向を `aimDirection` とする。

差分ベクトルの長さが十分小さい場合は発射を中止する。長さ0の正規化による非有限値を防ぐ。プレイヤーと弾モデルの null 判定も維持する。

### 4.4 放射方向を求める

1. `aimDirection` と平行でない基準軸を選ぶ。通常はワールド上方向を使い、ほぼ平行な場合は別の軸を使う。
2. 外積と正規化で、照準方向に直交する `rightDirection` と `upDirection` を作る。
3. 周囲弾の角度を `2π × bulletIndex / kRadialBulletCount` とする。
4. 周囲方向を `rightDirection × cos(angleRadians) + upDirection × sin(angleRadians)` で求める。
5. 発射方向を `aimDirection × cos(spreadAngleRadians) + 周囲方向 × sin(spreadAngleRadians)` とし、正規化する。
6. 各発射方向に `bulletSpeed_` を掛け、全弾の速さを揃える。

調整値は `kRadialBulletCount`（8）、`kSpreadAngleDegrees`（15）、退化判定用の定数として定義する。三角関数にはラジアンへ変換した値を渡す。

### 4.5 既存の弾を生成・登録する

`SpawnBullet` などの小さなメンバー関数に、通常弾の生成・初期化・位置設定・速度設定・登録をまとめる。中央弾と周囲弾から共通利用する。

NormalEnemyBullet 自体の動作は変更せず、登録後は既存の EnemyBulletManager と衝突判定に任せる。新しい弾クラスや弾モデルの追加は不要。

## 6. 検証と完了条件

- ビルドが成功し、既存の弾登録の呼び出し箇所が互換性を維持する。
- 通常敵1体の1回の射撃で、中央1発と周囲8発が同時に生成される。
- 周囲8方向の間隔が45度、照準軸との角度が15度、全弾の速さが等しいことを数値で確認する。
- 水平・斜め・ほぼ真上/真下への照準でも、方向が非有限値にならず正しく広がる。
- 敵と予測照準位置が一致する場合、プレイヤーやモデルが未設定の場合に安全に処理を終了する。
- ArmoredEnemy は単発のまま、MoveEnemy・他の敵・ボスの射撃も従来どおり動く。
- 1回の放射状射撃で発射音が1回だけ鳴る。
- 中央弾と周囲弾が既存の被弾処理で判定され、寿命・後方除去・シーン終了時の破棄が機能する。
- 30/60/120FPSで、弾速と広がり方を確認する。射撃頻度の差は既存仕様として記録する。
- 同じステージ・敵数・描画設定で変更前後を比較し、最大生存弾数、射撃時のCPU時間、通常フレームのCPU/GPU時間、FPSを記録する。通常の敵密度に加え、複数体が同時に撃つ条件も確認する。
- 実際の回避のしやすさを確認し、必要なら周囲弾数・拡散角を調整する。性能上の許容値は現在の実測を基準に判断し、未測定のFPS保証は行わない。

方向の数値確認は、既存の検証環境が使える場合は小さな検証で行う。専用の大きなテスト基盤は追加せず、実際のゲームでの見た目・音・衝突・性能の確認と組み合わせる。

## 8. 実装・検証結果（2026-10-13）

- 予定した5ファイルを変更し、中央1発＋周囲8発、拡散角15度、装甲敵の単発維持、発射音の重複抑制を実装した。
- エンジン側を軽量な代替にした検証用実行ファイルへ、実際の NormalEnemy.cpp と ArmoredEnemy.cpp をコンパイルして検証した。弾数、角度、等速、予測照準、ほぼ上下方向と基準軸切り替え付近、単発切り替え、初期化による放射設定の復元、null、ほぼ同位置、予測位置の一致、非有限な予測、射程外・後方への発射抑止、音の再生要求が1回であることを確認した。音声出力や描画そのものを検証したものではない。
- 実際のエンジンのヘッダーを使い、変更した3つの cpp を MSVC の `/Z7` で個別コンパイルし、成功した。
- Debug の全体ビルドは C1902（プログラムデータベースマネージャーの不一致）で失敗した。プロジェクトのビルド設定は変更していない。全体のリンク成功は未確認。
- 差分の空白検査は成功。新規コードに三項演算子とラムダ式は使用していない。
- 実ゲームでの見た目、音声、被弾、寿命・後方除去、FPS別動作、性能測定は未実施。性能値やゲーム全体の動作保証は、この検証結果に含まれない。
- 検証用の代替ヘッダー・ソース・実行ファイルは、Git 管理対象外の `generated/radial-shot-check/` に保存した。
- 追加指定により通常敵の弾速を0.8から0.48へ変更した。予測照準も変更後の弾速を使用する。発射処理の検証を更新して再実行し、全9発の速さが0.48、装甲敵の速さが0.8であることと、角度・照準・ガード条件の検証成功を確認した。
