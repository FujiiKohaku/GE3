# FearWormBattleState責務分割 実装計画書

作成日：2026-10-21  
状態：第1段階を実施済み。第2〜6段階は未着手。実施・検証記録は末尾に記載。

## 目的

FearWormBattleStateを、戦闘行動の選択・切り替え・更新の調整を中心としたクラスへ整理する。攻撃専用の処理と定数は各攻撃Stateへ、複数の行動で共有する移動・射撃は担当クラスへ移す。

攻撃の順番、優先度、弾道、発射間隔、移動、描画、ダメージ、登場・死亡時の動作を維持する。行数の削減だけを完了条件にしない。同じクラスの実装を複数のCPPに分けるだけでは完了としない。

## 現状と確認した依存関係

対象：`project/App/Game/Boss/FearWormEnemy/Battle/`。

`FearWormBattleState.cpp`は647行（空行・コメントを含む、作成時点）。各攻撃のStateは分割済みだが、BattleStateには以下が残っている。

| 分類 | 残っている主な処理 |
|---|---|
| 戦闘の統括 | Update、ChangeAction、FinishAction、Enter、Exit、Reset、激昂・ビームへの優先切り替え |
| 移動 | 6種類の目標座標計算、カメラの上下角による補正、頭の位置更新、移動用の経過時間 |
| 射撃 | 通常弾、拡散弾、強化弾、追尾ミサイルの生成、生存部位の選択 |
| 隊形 | とぐろと横並びの位置・補間率計算 |
| 頭の演出 | 強化弾攻撃中の色・脈動、照準方向、発射口、頭の回転計算 |
| 描画への接続 | ビーム初期化・描画・レイトレーシングの呼び出し |

依存関係上の注意点：

- EnemyのUpdateSegmentsが隊形計算を呼び出す。隊形は攻撃StateのUpdate内だけでは完結しない。
- Enemyの描画用更新が頭の色・拡縮・回転を問い合わせる。
- 登場処理はPrepareEntryMovementを通して移動を準備する。Enemy側の移動計算窓口とテストもBattleStateの型・関数に依存する。
- 現在、MovementTargetPositionはSpiralBarrageState内部の時間と角度を直接参照している。
- 通常行動の時間には速度倍率を使うが、とぐろ・激昂では実時間を使う。射撃にはフレーム単位のカウンターもある。
- ビームの段階・照準・移動制限はBeamStateへ、描画・姿勢・当たり判定はBeamへ移動済み。この分担を維持する。

HeadAimはHeadChargeとBeamで共有するため分離する。色・脈動・溜め時間はHeadCharge側に置く。汎用Utilクラスは追加しない。

## 第1段階：攻撃専用の処理と定数を各Stateへ戻す

共通基盤の大幅な変更に先立ち、利用先が限定される処理を移す。

| 現在の処理 | 移動先 | 一緒に移すもの |
|---|---|---|
| FireSpreadBullets | WeaveSpreadState | 拡散角、3方向の計算、まとめて1回再生する発射演出 |
| FireChargedBullet | HeadChargeState | 強化弾の速度・色・拡縮・威力・判定半径・寿命 |
| UpdateHeadAimDirection | HeadChargeState | HeadCharge専用の追従率。方向の補間自体は後でHeadAimへ委譲 |
| HeadAttackColor / ApplyHeadChargePulseの具体的計算 | HeadChargeState | 溜め・発射中の色、脈動の係数 |
| FireSingleMissile | LineMissileState | ミサイル生成・プレイヤー設定・発射演出 |
| 攻撃専用の間隔・回数 | 各対応State | HeadCharge、LineMissile、CoilBarrage、DriftBurstの専用定数 |

弾をEnemyの管理リストへ登録する仕組みは維持する。弾モデルなど共有資源の参照は、用途の明確な窓口を通して取得し、攻撃ごとにロードし直さない。

MakeRotateAxisAngleMatrixは、作成時点のFearWormEnemy配下の検索では定義・宣言以外の使用を確認できなかった。実装時にリポジトリ全体の参照を確認し、未使用なら削除する。新しい共通クラスへ未使用処理を移さない。

完了条件：該当攻撃の調整が、その攻撃フォルダ内の修正で済む。BattleStateに同じ処理・定数を残さない。

## 第2段階：共通移動をMovementへ分離する

移動対象：UpdateBattleMovement、BattleTarget、MovementTargetPosition、CalculateFearWormTargetと6種類の軌道計算、対応する型・定数・共有移動状態。

実施内容：

1. 移動種類と計算用コンテキストをMovement側の型にする。Enemy・登場処理・テストの型参照も更新する。
2. 周回角など、複数の行動で連続して使う状態をMovementが所有する。
3. Stateが指定する軌道・時間・角度を入力として受け取る。激昂の時間・角度をMovementから直接読ませない。
4. 行動時間の更新は各Stateへ移す。通常行動の速度倍率、とぐろ・激昂の実時間を維持する。
5. ビーム固有のX・Y固定はBeamStateに残す。共通移動には軸制限の判断を戻さない。
6. 登場時の移動準備と戦闘開始時の初期化を更新し、移動計算の二重実行を防ぐ。

軌道計算に必要なとぐろの期間などは、Stateから入力する。攻撃の期間設定をMovement側へ重複定義しない。

完了条件：Movementが具体的な攻撃Stateの内部を参照しない。登場・通常移動・ビーム移動の数値結果と更新順序が保たれる。

## 第3段階：隊形の判断を対応Stateへ移す

移動対象：CoilFormationBlend、IsCoilFiring、CalculateCoilSegmentPosition、とぐろの隊形合成、横並びの補間・揺れ、lineTransitionTimer。

- とぐろの形成・射撃可否・解除はCoilBarrageStateが同じ時間から判断する。
- 横並びの準備・補間時間・揺れはLineMissileStateが所有する。
- Enemyの通常の胴体追従と、生存順に部位を更新する処理は維持する。
- 通常の追従位置を入力し、攻撃による補正位置を返す窓口を行動側に設ける。既存のFearWormBattleActionに必要最小限の窓口を追加し、通常行動では入力位置をそのまま返す。
- 補間時間は1フレームに1回だけ更新する。部位ごとの問い合わせで時間を進めない。
- 追加の問い合わせは必要な範囲に限定する。部位配列のコピーや、部位ごとの動的確保を導入しない。

完了条件：BattleStateが攻撃ごとの隊形式・期間を持たず、通常追従への適用を行動側へ委譲できる。行動中断時に隊形の状態が残らない。

## 第4段階：共通射撃をShootingへ分離する

移動対象：FireBullet、FireDirectionalBullet、CanFire、SelectFiringSegment、共通の射撃設定・資源参照・部位選択状態。

- Shootingは指定された位置・方向で通常弾を生成し、Enemyへ登録する。
- 弾の配列・更新・破棄の所有は既存のEnemy側に残す。
- 拡散・連射・とぐろ・激昂などの弾道とタイミングの判断は各Stateに残す。
- フレーム単位の射撃間隔と、秒単位の連射間隔を維持する。
- 生存部位を巡回する順番は共有する。行動切り替え時に以前と違う初期化をしない。
- 強化弾やミサイル専用の詳細設定を、通常弾の生成クラスへ再び集めない。

完了条件：BattleStateから弾型の生成実装がなくなり、各Stateが必要な共通射撃機能を利用する。

## 第5段階：共有照準と頭の演出・描画接続を整理する

HeadMuzzlePosition、HeadLookRotation、headAimDirectionと共通の補間計算をHeadAimへ移す。HeadChargeとBeamの追尾率はそれぞれが指定する。

頭の色・脈動・照準の要否は行動側へ問い合わせる。必要な窓口をFearWormBattleActionに追加し、通常行動は元の色・拡縮、照準なしを返す。BattleStateがHeadChargeStateのprivateメンバーを読む構成を解消する。

ビームの表示可否のうち、待機状態・頭の生存状態などビーム専用の条件はBeamState側にまとめる。初期化・Draw・SubmitRaytracingの呼び出し窓口は統括側に残してよい。呼び出しを消すためだけにEnemyから各Stateの内部を直接触らせない。

完了条件：攻撃専用の頭の演出は各State内で調整できる。Beamの描画・判定・発射演出が同じ姿勢を使用し続ける。

### 追加実施：攻撃ごとの時間更新を各Stateへ移動

ユーザー指定の「① 攻撃ごとの時間の進め方」を実施した。第2段階全体の完了を示すものではない。

- BattleState::UpdateからmovementPatternTimerの加算と、とぐろ・激昂を特別扱いする時間倍率の分岐を削除した。

- ミサイルの段階時間とビームの段階時間は引き続き速度倍率を掛けずに進める。これらと共有移動タイマーを混同しない。

- movementPatternTimer自体は移動軌道・隊形が参照しているため、所有場所を維持した。移動・隊形の責務分離は後続作業とする。

検証結果：関連コードの再コンパイル、テスト実行ファイルの再ビルド、回帰テストに成功した。速度倍率が1より大きい状態で全8行動を確認し、State直接更新での時間加算、統括経由での二重加算防止、攻撃終了時のリセット、ミサイル割り込み待ち時間の維持を検証した。実画面は未確認。

### 追加実施：激昂Stateから移動計算へ値を渡す

ユーザー指定の「② 他のStateの内部値を読む処理」を、激昂の移動計算について実施した。

- SpiralBarrageStateが自身の時間・角度を更新してから、UpdateBattleMovementへ明示的に渡すようにした。
- 移動処理は受け取った値をBattleTarget、MovementTargetPositionへ引き継いで軌道を計算する。BattleStateからSpiralBarrageStateのelapsedSeconds・spiralAngleを直接読む処理を削除した。
