# Kohaku Effect Editor

KohakuEngineを共有する独立したWindowsアプリです。日本語の画面でパーティクルとポストエフェクトを編集します。
モデルプレビューと同様にエンジンのソース・依存ライブラリを利用し、ゲームとは別の実行ファイルと中間ファイルを生成します。

## 起動

リポジトリのルートからPowerShellで実行します。

```powershell
./project/Tools/StartEffectEditor.ps1
```

再ビルドして起動する場合：

```powershell
./project/Tools/StartEffectEditor.ps1 -Build
```

Visual Studioでは`project/KohakuEngine.sln`の`EffectEditor`をスタートアッププロジェクトに設定し、`Release / x64`で起動してください。
実行ファイルは`generated/outputs/Release/EffectEditor.exe`です。実行時のresourcesは元のプロジェクトと共有します。

## 画面と基本操作

- 上：パーティクル／ポストエフェクトの切り替え、保存、元に戻す、やり直し、適用、シェーダー再読み込み。
- 左：種類別の粒子一覧、新規作成・複製、テクスチャ。またはポストエフェクトのプリセット一覧。
- 中央：エンジンによる実際の描画。再生・一時停止・一回再生／ループ・速度・発生源の移動を調整できます。
- 右：選択した対象の日本語プロパティ。粒子は基本・描画・フィールド・ライトに分かれています。
- 下：ポストエフェクトの有効／無効、追加、並べ替え、個別設定。行を右クリックすると削除できます。

プレビュー内で右ドラッグするとカメラが回転し、中ドラッグで移動、ホイールでズーム、`F`で初期位置に戻ります。
プレビューの右クリックメニューで背景色とOBJモデルを選べます。
`F11`で全画面／ウィンドウ表示を切り替えます。「表示」メニューからも切り替えられます。
`Ctrl+S`で現在の編集対象を保存、`Ctrl+Z`で元に戻す、`Ctrl+Y`でやり直します。
色の帯をクリックするとカラーピッカーが開きます。

粒子の変更は「適用して再開始」で反映します。保存時も検証と適用を行います。
画面効果の変更は有効な値だけを自動反映します。失敗した場合は画面下に理由を表示し、それまでの有効な設定を維持します。
編集対象の切り替え・新規作成・終了では未保存の変更を確認します。複製は編集中の値を新しい対象へ引き継ぎます。

## 起動したまま外部から変更する

上部の「外部変更を自動反映」は初期状態で有効です。同じプロジェクトのファイルをCodexやテキストエディターで編集して保存すると、アプリを閉じずに反映します。

- 選択中の粒子の`Effect.json`：検証後に設定欄とプレビューを更新し、粒子を再開始します。
- 選択中のポストエフェクトのプリセットJSON：検証後に設定欄と画面効果を更新します。
- 選択中の粒子の発生・更新・頂点・ピクセルシェーダー、共通の初期化・フィールド処理：再コンパイル後に切り替えます。
- 読み込んだポストエフェクトのシェーダー：ブルーム・霧・最終合成も含め、再コンパイル後に切り替えます。
- 上記から直接・間接にincludeされるファイルの変更も検知します。

監視は200ミリ秒ごとです。保存途中を読み込まないよう、最後の変更から400ミリ秒以上安定してから処理します。
検知はおおむね0.6〜0.8秒後で、そこにコンパイル時間が加わります。コンパイルとGPUの切り替え中は一時的に画面が止まる場合があります。
一時停止中も監視します。「外部変更を自動反映」を外すと監視を保留し、有効に戻すとその間の変更を確認します。

シェーダーは新しい描画設定の準備がすべて成功してから切り替えます。
文法エラーや現在のリソース割り当てと合わないシェーダーでは、最後に成功したプレビューを維持します。
上部の「再読み込みエラー」で全文を表示・コピーできます。修正して保存すれば再試行します。
JSONで新しく指定したシェーダーが失敗した場合も、そのシェーダーを修正すると保留中の設定の適用を再試行します。
「シェーダー再読み込み」は、現在選択している粒子／ポストエフェクトを手動で再読み込みするボタンです。

画面に未保存の編集がある場合、外部JSONの変更は保留します。
「外部変更あり」から「外部の内容を読み込む」「画面の編集で上書き保存」「あとで決める」を選択できます。
通常の保存でも保存先を確認するため、自動反映を切っていても外部の変更を無断で上書きしません。
外部の設定を採用した後でも「元に戻す」で以前の画面の内容を取り出せます。

コードの変更に使える指示例：

> 現在プレビューしている粒子のEffect.jsonで、開始色を青にして速度を遅くしてください。
> エディターは起動したまま、自動反映で確認します。

監視するのは選択中・読み込み済みの対象です。別のチェックアウトのファイルやC++の編集は自動反映の対象外です。
CPU側の構造体・定数バッファ配置・リソースの割り当てを変える編集や、UIそのものの変更にはビルドと再起動が必要です。

## データ

粒子は`project/resources/Effects/<識別名>/Effect.json`へ保存します。
新規作成は既存のMesh／Trailテンプレートのシェーダーを新しいフォルダーへ複製します。
識別名は英数字・`_`・`-`、表示名は日本語を使えます。
`Render.Type`は`Mesh`または`Trail`で、作成後は固定です。
既存の未知のJSON項目は保持します。保存は一時ファイルから置き換え、書き込み失敗時は元のファイルを維持します。

ポストエフェクトは`project/resources/Graphics/PostEffects/<名前>.json`へ保存します。
標準・氷の空気感のプリセットを同梱しています。
`effects`に種類・有効状態・順序、`parameters`に共通設定、`effectParameters`に効果固有の3値、
`bloom`、`atmosphere`、`finalPass`に各設定を保存します。
同じ効果の重複や不正な描画位置は拒否します。

ゲーム側では、初期化済みの`PostEffectManager`へ同じファイルを読み込めます。
GPUの描画命令を記録していないフレーム境界で呼び出してください。
SceneManagerが管理する現在の画面効果と霧・露出も更新します。
シーン側で独自に上書きしている設定がある場合は、シーンの読み込み後に適用してください。

```cpp
std::string error;
bool isLoaded = postEffectManager.LoadPreset(
    "resources/Graphics/PostEffects/MyPreset.json", error);
```

PNGは`project/runtime/captures/EffectEditor/`へ保存します。UIを含まないプレビュー画像です。

## エンジンとの共有範囲

`DirectXCommon`、`EffectManager`、`Object3d`、`OffscreenRenderer`、`PostEffectManager`、カメラ・ライト・テクスチャをそのまま利用します。
エディター独自のパーティクルPSOやシミュレーションは作成していません。
エディター側の`PreviewTarget`はエンジンが描いた最終画像をUI内に表示するための出力先です。
GPU使用終了後に粒子の適用・シェーダー再読み込み・保存を処理します。
一時停止中の新規GPUバッファも初期化してから描画します。

ポストエフェクトの「粒子の前／粒子の後」はエンジンの描画段階に従います。
ブルームは最終合成、FXAAとトーンマッピングは最終処理で設定します。
順序の入れ替えは同じ描画段階の中で行います。

追加コストは最終プレビュー用のRGBA画像（ウィンドウ時1280×720で約3.5MiB、全画面時1920×1080で約7.9MiB）とその表示です。
HDR画像、深度、各ポスト処理のバッファ・描画負荷は通常のエンジンの処理に従います。
粒子は選択時に登録するため、起動時にすべての粒子のGPU資源を作りません。

## 現在の範囲と検証

ウィンドウ時は1280×720です。F11でモニター全体を覆う枠なし全画面に切り替え、1920×1080で描画します。
全画面から戻すと元の位置・サイズを復元します。任意のドッキング、ノード編集、カーブ／タイムライン、GIF出力は未実装です。
既存の粒子シェーダーが持つ設定を編集する方式で、シェーダーの動作自体は各アセットに依存します。
効果固有の3値は、名前が定義されていないものは「調整値1〜3」と表示します。

検証した構成はRelease / x64です。エディターの実機テスト、既存のEffectEditingTests、エンジン本体のビルドと最初のフレームまでの起動・終了を確認しています。
エンジン本体には、既存の中間PDBの型情報に関するLNK4020警告が残っています。実行は成功していますが、そのPDBを使うデバッグ情報には制限があります。

実機スモークテスト：

```powershell
./generated/outputs/Release/EffectEditor.exe --smoke-test
```

実際のDX12で通常粒子・トレイルの作成、複製、元に戻す／やり直し、適用・保存、一時停止中の適用、
種類変更の拒否、ループ無効の維持、プリセット検証・保存・再読み込みを確認します。
外部JSONの反映、未保存編集との競合、保存の競合保護、HLSL/includeの失敗と修復、描画設定の互換性エラーも確認します。
失敗するポストシェーダーのテストにはruntime内のコピーを使い、元のシェーダーは変更しません。
テスト用に固有名のアセットを作成し、成功後にそのテスト用フォルダーだけを削除します。
画面のPNGを`project/runtime/EffectEditorSmoke/`へ出力します。
