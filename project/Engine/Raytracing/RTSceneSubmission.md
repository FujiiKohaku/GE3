# RTシーン登録と通常描画の分離

`Object3d::SubmitRaytracing(DxrRenderer&)` と `SkinningObject3d::SubmitRaytracing(DxrRenderer&)` は、通常描画を行わずRTへモデルを提出します。画面外で `Draw()` を省いた物体も、影・反射・RTGIの光線が参照できます。

## シーンからの提出

`BaseScene::SubmitRaytracingScene(DxrRenderer&)` をオーバーライドします。RendererはDXRが有効なフレームで、通常の `Draw3D()` の前にこの入口を呼びます。

```cpp
bool SampleScene::SubmitRaytracingScene(DxrRenderer& renderer) {
    for (const auto& object : objects_) {
        if (object) { object->SubmitRaytracing(renderer); }
    }
    return true;
}
```

モデルの `Update()` は提出前に済ませます。提出は更新済みのワールド行列・材質・GPUスキニング頂点を使用し、アニメーションやモーションベクトルの描画・コピーは追加実行しません。ポーズを停止している場合はその頂点を使います。

戻り値trueは、そのシーンがRT対象をすべて提出したことを意味します。RendererはそのフレームのDraw経由の登録を無効にします。falseなら追加の提出と従来のDraw経由の登録を併用します。未対応シーンの既定値はfalseです。同じオブジェクトを重複提出してもTLASへ1回だけ登録します。

タイトル、ゲームプレイ、TestScene1は専用提出へ接続済みです。ゲームプレイはレベル、回収アイテム、床、魚・鳥、プレイヤーと弾、シーン管理オブジェクト、敵と弾、ボスの部位を提出します。死亡・回収済み・部位破壊・タイトルの部屋切り替え・プレイヤーの点滅など、元の表示上の参加条件を維持します。専用描画の海面、水柱、空、パーティクルは現在のDXR対象外です。他のシーンは互換経路を使用します。

## 2つの範囲判定

通常描画は `SetFrustumCullingEnabled(true)` を設定したモデルで、カメラのジッターを除いた視錐台と境界球を照合します。既定はfalseです。`IsVisible(camera)` で同じ判定を取得できます。視錐台外では色描画・モーション描画を省きます。RTへの提出は別途行うため、RTの影・反射・GIは視錐台外でも成立します。カリングは色描画に適用し、シャドウマップ用のDrawShadowを省くものではありません。

RTの選別は `DxrRenderer::SetSceneCullingSphere(center, radius)` です。BeginFrameの後、最初のモデル提出より前に指定します。ワールド空間の球とモデルの境界球が離れている場合だけ除外します。半径0は選別OFFです。非有限値・負の半径・提出開始後・フレーム外の設定はfalseを返します。設定はフレームごとに初期化されるため、必要ならシーンの提出入口の先頭で毎フレーム設定してください。

静的モデルはモデルの境界球と更新済みワールド行列を使用します。非一様スケール・シアーも含めた安全側の拡大率を使います。独自頂点シェーダーの変形はRT対象外で、通常描画の境界判定も省きます。

スキニングモデルは既定では境界が不明です。静止姿勢の境界で変形後の頂点を誤って切らないよう、範囲が不明なら描画・RTとも残します。`SetRaytracingBounds(DxrSceneBounds)` へ、現在の変形頂点全体を含むモデルローカル空間の球を渡すと、通常描画とRTの両方で境界を使えます。`DxrSceneBounds{}` で未指定へ戻します。姿勢が変わる場合も、指定した球が全頂点を含むことを呼び出し側で維持してください。低レベルの `QueueDeformed` は任意のワールド境界を渡せます。

RT範囲は光源・反射・間接光の寄与範囲に合わせて設定します。小さくすると範囲外の遮蔽物や光源となる面も消えるため、既定では範囲選別を行いません。ライトごとの影響領域、空間ツリー、距離LODを自動構築する処理は未実装です。

## 参加と寿命

`SetRaytracingEnabled(false)` は、専用提出・Draw経由の提出・RT用キャプチャへの参加を止めます。通常の色描画は維持します。透明ブレンド、切り抜きなしのalpha不足、未対応頂点シェーダー等の既存の除外条件も使用します。SkinningObject3dは従来どおりブレンドなしの経路を対象にします。

登録リストはBeginFrameで空にします。次のフレームで提出しないモデルはTLASから除かれます。削除済みオブジェクトを後から呼び出す永続登録リストは持ちません。削除する際は所有コンテナからも取り除き、描画中にオブジェクトやモデルを破棄せず、既存のフレームフェンス完了後に行います。GPUリソースの保持・退避は既存DXR基盤と共有します。

低レベルのフレーム順序は `BeginFrame → 範囲設定 → モデル提出 → 通常描画 → EndFrame` です。`SetDrawSubmissionEnabled(false)` で互換登録だけを止めても、明示的なQueue・SubmitRaytracingは有効です。この設定もBeginFrameで初期化します。

## 実行コスト

今回の画像・GPUパイプライン・レイ本数の追加はありません。提出リストの走査と選別はモデル数に比例し、重複判定はIDのハッシュ集合で平均O(1)です。ID集合のCPUメモリはO(N)です。通常描画の視錐台判定はモデルごとの境界変換と6平面の判定です。

画面外のモデルを追加で提出した分だけBLAS・TLAS・材質バッファ・ヒットレコードと探索対象が増えます。静的モデルのBLASは共有し、変形モデルはオブジェクトごとに保持します。初めて提出した変形モデルはBLAS構築、姿勢変更時はrefit、同じ姿勢なら再利用します。範囲外から戻ったモデルは必要に応じて再構築します。既存の容量を保持するバッファもあるため、除外した数に比例して毎フレームVRAMが減るとは限りません。

DXR Foundationと開発パネルで登録数・RT範囲外の数・BLAS数・構築時間・バッファ容量を確認できます。シーンごとの追加モデル数によってGPU時間とVRAMが変わるため、固定の追加msやMiBにはなりません。

## 検証

`DxrTests.exe` は通常描画を呼ばない太陽光・局所ライトの遮蔽物、反射対象、GI光源、GPUスキニングモデルを検証します。描画側の視錐台カリング、RT範囲、重複、参加OFF、追加・削除、明示的に空のRTシーン、変形境界の未指定・指定・範囲復帰とrefitも確認します。視錐台の6方向、近クリップ境界の交差、シアー、無効な境界・行列の保守的な処理も検証します。全DXRテストはD3D12検証レイヤーのERROR/CORRUPTIONを失敗扱いにします。結果とPNGは `runtime/captures/DxrTests` に保存します。

2026-10-09、RTX 4060 Laptop GPUで全DXR GPUテストが成功しました。専用登録の結果は `scene-submission-result.txt`、描画を省いたモデルの反射・GI・太陽光・局所ライト影・スキニングのPNGも同ディレクトリに保存しています。Development構成のエンジンビルドも成功しています。これらは登録と描画結果の検証で、ゲーム全体の性能測定ではありません。
