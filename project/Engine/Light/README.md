# ライトの設定と局所ライトの影

`LightManager` にライトを登録し、シーンからSetterで設定します。描画と影のGPUリソースはエンジンが管理します。太陽光、環境光、ポイントライト、スポットライトに対応します。

## 複数ライト

```cpp
LightManager* lights = LightManager::GetInstance();
PointLightHandle pointHandle = lights->AddPointLight(
    { 0.3f, 0.6f, 1.0f, 1.0f }, { 30.0f, 20.0f, 100.0f },
    0.5f, 150.0f, 2.0f);
lights->SetPointLightShadowEnabled(pointHandle, true);
lights->SetPointLightPosition(pointHandle, { 35.0f, 20.0f, 100.0f });

SpotLightHandle spotHandle = lights->AddSpotLight(
    { 0.8f, 0.9f, 1.0f, 1.0f }, { 0.0f, 80.0f, 100.0f },
    { 0.0f, -1.0f, 0.3f }, 0.7f, 200.0f, 2.0f, 0.72f);
lights->SetSpotLightCosFalloffStart(spotHandle, 0.90f);
lights->SetSpotLightShadowEnabled(spotHandle, true);
```

色・位置・強度・到達距離・減衰は個別のSetterで変更できます。スポットライトは方向、外側の角度のcos値、内側のぼかし開始角度のcos値も設定できます。cos値が大きいほど角度は狭くなります。内側の値は外側の値より大きく、1以下で指定します。

ポイントライトは32枠、スポットライトは8枠です。各0番は既存の単一ライトAPI用なので、動的に登録できる数は31個と7個です。満杯または不正な入力では `kInvalidPointLightHandle`／`kInvalidSpotLightHandle` を返します。更新のbool戻り値がfalseなら値は変更されません。

NaN・無限大、ゼロの方向、不正な距離や角度を拒否します。到達距離は0.1より大きく10000以下、強度とRGBは0～64、減衰は0～16です。ハンドルには世代を含み、削除後に再利用された枠へ古いハンドルから書き込むことを防ぎます。ハンドルを配列インデックスとして使用しないでください。`GetPointLight`／`GetSpotLight` の引数は内部のライト枠番号です。

不要になったライトは `RemovePointLight`／`RemoveSpotLight` で削除します。`SceneManager` は次のシーンを初期化する前に動的ライトをクリアし、単一ライトの強度と影フラグもリセットします。遅れてFinalizeされる旧シーンのハンドルで新しいライトは削除されません。エンジンだけを使用するアプリは、自分のライフサイクルに合わせてクリアしてください。

## 影

`Renderer` が `LocalShadowRenderer` を所有します。既存の `ShadowMapRenderer` に透視投影と共有深度配列への描画を追加し、既存の物体の `DrawShadow` を再利用しています。

- スポットライト：最大2個、各1面。
- ポイントライト：最大1個、6方向の影。
- 1面512×512、深度配列8面で約8MiB。方向光の影とは別の画像。
- ライト登録順に相当する枠番号の小さいものから影を割り当てます。上限を超えた影要求は影なしの照明になります。
- 初期状態は影なしです。`SetPointLightShadowEnabled`／`SetSpotLightShadowEnabled` で個別に指定します。0番を渡すと既存の単一ライトにも指定できます。
- 強度0、無効なライトでは影を描きません。影を要求するライトがあるときだけ専用リソースを作ります。
- 球の範囲と各影面の視錐台で物体をカリングします。PCFは3×3です。
- リソース作成失敗時はログを残し、そのライトは影なしで照明を続けます。毎フレームの描画完了を確認し、古い影を流用しません。

物体側は `SetCastShadow(true)` と `SetReceiveShadow(true)` を設定します。通常材質、ShadowToon、氷の地形・床、クラゲボスが局所ライトとその影を受けます。既存の影用描画に対応していないモデルは影を落としません。従来のスキニング用シェーダーは局所照明に対応しますが、局所影の受け取りは未対応です。発光・Unlit材質は照明の影響を受けません。ポイントライトの面境界には低解像度による継ぎ目が出る場合があります。

スポットライトは `SetSpotLightVolumetricEnabled(handle, true)` で立体霧へ散乱できます（最大2灯、初期状態は無効）。影を有効にしたライトでは当該フレームの局所影を参照し、影が未完了・上限外なら散乱を省略します。点光源の霧への散乱は未対応です。詳細は `Engine/PostEffect/Volumetric/README.md` を参照してください。

## 見た目の調整

`resources/Graphics/visual-presets.json` で太陽光と環境光を調整しています。stage03では環境光を抑え、クラゲボスへ薄い青のスポットライトと補助のポイントライトを配置しました。クラゲの反射も抑え、表面の形が読みやすい設定にしています。

シーンの露出は `SceneManager::SetSceneExposure()` で0.1～4を指定します。シーン切替時に1へ戻し、`PostEffectManager` が変更時だけ反映するため、開発パネルで露出を調整した値は毎フレーム上書きされません。stage03の既定値は0.95です。

## 負荷と検証

影なしの複数ライトはピクセルごとの計算が増えます。到達距離外、強度0、無効なライトの計算を省略します。影付きライトは追加のジオメトリ描画を必要とし、ポイントライト1個は最大6回です。

`ShadowMapTests` はポイント／スポットの照明と遮光、同時使用、ハンドル世代、入力検証、D3D12の検証を行います。`--stage` は実際のstage03、`--title` はタイトルの回帰確認です。

単純な床＋氷モデルでの測定値（1280×720、影512×512、デバッグレイヤー有効、ウォームアップ後20回平均）：

| 設定 | 影・物体描画・後処理の合計 |
|---|---:|
| 局所ライトなし | 0.140ms |
| ポイントライト、影なし | 0.148ms |
| ポイントライト、影あり | 0.197ms |
| スポットライト、影なし | 0.149ms |
| スポットライト、影あり | 0.181ms |
| ポイント＋スポット、両方影あり | 0.225ms |

これは実ゲームの保証値ではありません。ライトと影の差は影なしを基準に約0.05ms／約0.03msですが、実ゲームでは影を描く物体数に応じて増えます。テスト結果は `runtime/captures/ShadowMapTests/local-light-timing.txt` に出力します。

## 間接光・大気散乱・Clustered（④〜⑥）

既存のクラスを拡張しています。ライティング設定は `LightManager`、SSAOは `PostEffectManager`、空は `SkyBoxManager` から使用します。描画順は、不透明物体 → SSAO＋遠景の大気散乱 → 立体霧／光の筋 → シーンの後処理 → パーティクル → ブルーム／トーンマッピング → UIです。SSAOと大気散乱は既存のHDRピンポン画像を使う1パスにまとめています。

```cpp
postEffectManager->SetSsao(true, 0.25f, 6.0f, 0.08f);
LightManager* lightManager = LightManager::GetInstance();
lightManager->SetEnvironmentLighting(0.12f, 0.20f);
lightManager->SetAtmosphere(true, 0.00035f, 0.45f, 0.65f);
lightManager->SetClusteredLightingEnabled(true);
```

数値設定のSetterは不正な範囲やNaN／無限大を拒否し、bool戻り値で結果を返します。各機能の強度は全体設定です。環境光の反射は材質側の `roughness`、`metallic`、`specularStrength` でも個別に変わります。既存の `enableEnvironmentMap`／`environmentCoefficient` による追加反射は残しています。

### SSAO

`SetSsao(isEnabled, strength, radius, bias)` は強度0〜0.6、ワールド単位の半径0.1〜30、自己遮蔽を防ぐバイアス0〜半径を指定します。深度からカメラ相対位置を復元し、周囲16点と法線を使って接触部を暗くします。固定サンプルなので時間によるランダムな点滅を起こしません。画面外、背景、半径外のサンプルは使いません。法線の深度タグが合わない画素も除外します。触腕の法線タグにも対応しています。

カメラ／深度がない場合はパスを省略し、法線がない場合はSSAOだけを省略します。強度0では色を変えません。UIと後から描くパーティクルには適用しません。

この版は合成済みのForward色を減衰させる方式のため、直接光・発光の色も少し暗くなります。間接光だけに適用するには照明成分を分ける追加バッファ、または先行深度・法線パスが必要です。画面外の遮蔽物は扱えず、サンプル不足や動く輪郭の変化も完全には消えません。時間蓄積や別のぼかしパスは追加していません。

### 環境マップの照明

拡散光は半球6点の積分近似、反射は粗さに応じたキューブマップのMip参照とFresnelで計算します。Standard材質、氷の床・地形、クラゲに対応します。床は拡散光のみです。Unlit、専用Toon、Archive材質にはこの追加照明を適用しません。

既存の静的キューブマップを使います。事前に畳み込んだirradiance／GGX環境マップを生成する本格的なIBLではありません。Mipによるぼかしは近似で、空の太陽を動かしてもキューブマップは更新しません。低周波の環境光と材質の反射差を出すための初期実装です。

### 大気散乱

`SetAtmosphere(isEnabled, density, strength, anisotropy)` は距離減衰の密度0〜0.01、散乱強度0〜2、前方散乱0〜0.9を指定します。空と遠景は同じRayleigh／Mieの単一散乱近似を共有し、方向光の方向・色・強度を参照します。夕方は波長ごとの減衰で色が変わり、太陽を弱めると散乱と太陽の表示も弱まります。

密度は遠景の透過率に使い、強度は空と遠景の散乱色に使います。既存の距離霧と立体霧は残っているため、併用時は濃さを調整してください。光の筋の遮光は従来のボリューメトリックライトが担当します。地球の球形大気を数値積分するモデル、多重散乱、LUT、雲の散乱は未対応です。

### Clustered Forward

12×8の画面タイルと、近／遠クリップ間を対数分割する16層を使います。CPUが各ライトの球の投影範囲へビット集合を登録し、PSは所属クラスタのライトだけを順番に計算します。スポットは到達距離の球で広めに分類し、円錐はPSで判定します。上限は引き続きポイント32枠・スポット8枠です。影の上限も変更していません。

全クラスタ×全ライトの総当たりを避け、ライトが重なる範囲だけを走査します。境界には余白を取り、ライトの消失を防ぎます。画面外・クリップ範囲外、不正なカメラ、機能OFFでは従来の全ライト走査へ戻ります。追加のGPUバッファは既存の環境光CB内に約24KiBです。ライトやカメラを更新した後、`Renderer::Draw` が毎フレーム `UpdateClusters(camera)` を呼びます。独自に描画するアプリでもその順序で呼び、描画中にライトを書き換えないでください。

開発パネルの「ライティング」で各機能のON／OFF、SSAOの半径／バイアス、環境光、大気散乱を調整できます。

### 検証結果

`ShadowMapTests` でSSAOの効果、静止画像の一致、強度0／法線欠落のフォールバック、大気散乱と環境光の画像差、38灯のClustered ON／OFFを確認します。カメラ3方向でClusteredと全走査の画像が完全一致することを必須にしています。

測定は1280×720、床＋氷モデル、デバッグレイヤー有効、ウォームアップ後20回平均です。GPUの物体描画＋後処理、CPUのクラスタ分類を別々に記録します。実ゲームの性能保証ではありません。結果は `runtime/captures/ShadowMapTests/screen-lighting-report.txt` と `clustered-lighting-report.txt` に出力します。

今回の測定値（GPUは物体描画＋後処理を含む）：

| 機能 | GPU時間 |
|---|---:|
| 追加機能OFF | 0.094ms |
| SSAOのみ | 0.277ms |
| 遠景の大気散乱のみ | 0.101ms |
| 環境光のみ | 0.134ms |
| 3機能を併用 | 0.331ms |

38灯・3カメラで、全ライト走査はGPU約0.278〜0.462ms、Clusteredは約0.166〜0.328msでした。CPU分類は約0.073〜0.137msです。CPUとGPUは別の測定なので単純合算はできず、この方式が常に高速になるわけではありません。画面解像度、ライトの到達範囲、CPU／GPUのどちらが詰まっているかで効果が変わります。分類結果はCPUの通常RAMで作り、一度だけUploadメモリへ転送します。Releaseの `LightManager.cpp` は速度最適化を明示しました。
