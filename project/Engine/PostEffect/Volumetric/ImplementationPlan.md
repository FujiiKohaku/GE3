# 場所ごとに濃度が変わるボリューメトリックフォグ実装計画

## 目的

地面付近、谷、ボスの周囲などに霧を配置し、奥行きと物体の大きさを感じやすくする。霧の内部では既存の太陽光とシャドウマップを利用して光の筋を描く。本計画に基づく初期版は実装済み。使用方法と制限・測定値は同じフォルダの `README.md` を参照する。

## 現在の実装と変更方針

既存の `VolumetricLightRenderer` は半解像度で視線をサンプリングし、均一密度の光の散乱を画面に加算している。`Raymarch.PS.hlsl` は影を参照し、`Composite.PS.hlsl` は深度の差を使って輪郭へのにじみを抑えている。現在の中間テクスチャのRGBは散乱光、Aは表面までの距離である。

この処理を拡張し、新しいレンダラークラスは作らない。設定用の `FogVolumeSettings` 構造体と形状を表す `FogVolumeShape` 列挙型を追加する。霧の計算とリソースの管理はエンジン、配置と演出はAppのシーンが担当する。

## 初期版の対応範囲

- 球と軸に沿った箱の局所霧。最大8個。回転した箱は後回し。
- 高さに応じて薄くなる地表の霧。
- 空間に固定した滑らかなノイズと、速度を指定したゆっくりした移動。
- 太陽光1つの散乱、影による遮光、背景や物体の減衰。
- 霧の中心、範囲、濃度、境界のぼかし、共通の霧色をSetterから変更。

初期版ではスポットライト、多重散乱、3Dグリッド、時間方向の再投影、霧ごとの個別色は実装しない。透明物への霧の適用は現在の描画順を確認して別途判断する。

## 設定API案

`FogVolumeSettings` の公開データは `isEnabled`、`shape`、`center`、`halfExtents`、`radius`、`density`、`edgeSoftness` とする。形状に使用しない項目は計算対象から外す。

既存レンダラーに以下のSetterを追加する。数値は現在のワールド座標と同じ単位とし、時間は秒で扱う。

- `SetLocalFogEnabled(bool isEnabled)`
- `SetFogVolume(uint32_t volumeIndex, const FogVolumeSettings& settings)`：成功時にtrueを返す。
- `ClearFogVolumes()`
- `SetHeightFog(float baseHeight, float density, float heightFalloff)`
- `SetNoiseParameters(float scale, float strength, const Vector3& velocity)`
- `SetFogColor(const Vector3& color)`

シーン初期化で設定し、終了時またはシーン切替時に局所設定をクリアする。所有する設定値をコピーして保持し、シーンの変数へのポインターは保存しない。開発パネルにはシーンのGetter／Setterを登録して調整する。

## 密度の計算

各サンプル位置で、高さ霧と局所霧を加算して密度を得る。局所霧モードでは既存の均一密度は使用せず、霧の外への影響を避ける。球と箱の境界には滑らかな減衰を付ける。高さ霧は基準高さより上で指数的に薄くし、下では密度を上限に固定して極端な濃度を防ぐ。

ノイズは最終密度に乗算する。強度0なら元の密度、強度1なら濃淡が強い状態になるようにする。空間座標を入力にした補間付きノイズを使用し、毎フレーム乱数を変えない。霧がない場所にノイズだけで霧を発生させない。

一定密度を前提にした現在の減衰式を、視線に沿って積み重ねる方式へ変更する。各区間で `segmentTransmittance = exp(-density * stepLength)` を求め、累積透過率を更新する。散乱光は区間の減衰量、更新前の累積透過率、位相関数、光色、影の可視率から求める。十分に不透明になった視線は早期終了する。

影は光の散乱にだけ作用する。遮光されても霧の密度と物体の減衰は残す。霧内の光源方向の減衰を追加で積分する処理は初期版では行わない。

## 画面への合成

散乱光を加えるだけでは濃い霧で背景が薄くならないため、以下の合成へ変更する。

`finalColor = sceneColor * transmittance + fogColor * (1 - transmittance) + scatteredLight`

ここで `fogColor` は環境光による霧の見た目を簡易的に表す設定色とする。

既存のRGB散乱光＋A深度のテクスチャは維持し、透過率用の半解像度 `R16_FLOAT` ターゲットを追加する。レイマーチで2つのターゲットへ同時に出力し、合成では深度に基づく同じ重みを散乱光と透過率に適用する。互換性のある深度サンプルがない場合は、散乱光0・透過率1として処理する。

既存の距離フォグは独立した効果として残すが、同じシーンで両方を強く設定すると霧が重なる。局所霧を導入するシーンは、距離フォグを遠景向けに弱く調整する。UIを描く前のHDR画面に合成する。

## 実行コストの見積もり

現行の半解像度・32サンプルを基本とする。1280×720の場合、640×360×32で約737万サンプル／フレームとなる。各サンプルで最大8個の霧を評価すると、上限は約5900万回の形状評価になるため、常時8個を使う前提にはしない。

CPUでは最大8個の設定コピーと定数バッファ更新が中心。GPUでは形状評価、ノイズ、透過率計算が増える。無効な霧を除外し、描画範囲と交差しない霧を除外して有効個数を減らす。高さ霧・ノイズは無効時に計算を省略する。

透過率テクスチャの追加メモリは1280×720時に画素データとして約0.44MiB。実際のGPU割り当てにはアライメント分が加わる。追加の出力帯域と合成時の読み取りも発生する。

処理時間のms値はGPUによって変わるため現時点では断定しない。GPUタイムスタンプで既存方式と比較する。低負荷設定は16サンプル・局所霧2個・ノイズなしを候補とし、品質設定は測定結果から決める。

## 安全策

- NaN、無限大、負の密度、不正な範囲、上限外のインデックスをSetterで拒否する。
- サイズと境界幅のゼロ割りを防ぎ、密度と透過率を有限な範囲に制限する。
- シャドウマップが無効な場合も、深度とカメラが有効なら霧の減衰と環境色は描く。散乱光は省略する。
- 深度・カメラ・リソースが無効な場合はそのフレームの効果を省略し、ゲームの描画は続ける。
- リソース生成が一部失敗した場合も中途半端な合成を行わない。追加ターゲットの状態遷移とSRV寿命を管理する。
- 時間によるノイズ移動量を制限し、大きな座標での精度低下を確認する。フレームごとのランダム変化を避けてちらつきを抑える。

## 実装順序と確認

1. 設定構造体、Setter、シーン切替時のクリアを追加。範囲・有限性・上限チェックを確認する。
2. ノイズなしの球と箱の密度を実装。境界、重なり、カメラが霧の内部に入った場合を確認する。
3. 透過率ターゲットと合成を追加。背景の減衰、影の内外、輪郭のにじみ、距離フォグとの重複を確認する。
4. 高さ霧と滑らかなノイズを追加。静止カメラ・移動カメラの両方でちらつきと縞を確認する。
5. 開発パネルへ設定を登録。テストシーンで確認した後、クラゲボスの足元へ薄い霧を配置する。
6. GPU時間を測定し、サンプル数・霧の個数・ノイズの有無を調整。Releaseと開発用構成をビルドする。

レイマーチのサンプル間隔より小さい霧は、縞や消失が出る可能性がある。初期版は広い薄霧を対象にし、薄い霧の品質が不足する場合は交差区間に限定したサンプリングを次の改善項目とする。

## 完了条件

球・箱・高さ霧をSetterで配置でき、霧の外では元の画面を保つ。霧内の物体が自然に薄れ、影に応じた光の筋が見える。シーン切替で設定が残らず、シャドウマップを無効にしても霧とゲーム描画が破綻しない。静止・移動時の目立つちらつきがなく、測定したGPUコストを記録できていることを完了条件とする。

実装時は既存の命名規則を守り、新しいコードに三項演算子とラムダ式を使用しない。
