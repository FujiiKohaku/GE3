# STAGE1：浮遊遺跡の守護兵器

生成した敵デザインシートを参考にしたローポリモデル5種類。青黒い古代金属、砂岩、赤橙色の目、青緑の結晶を共有し、ペイント敵には紫のタンクを追加。ゲームでは本体と可動パーツを分け、Translateで動かす。

| モデル | 意匠 | 三角形 | 材質数 | ゲーム内の最大半径 |
|---|---|---:|---:|---:|
| NormalEnemy.obj | 単眼の浮遊石像 | 552 | 4 | 2.64 |
| MoveEnemy.obj | エイ型の滑空兵器 | 494 | 4 | 2.7 |
| ArmoredEnemy.obj | 殻と大砲を持つ重装兵器 | 636 | 4 | 2.704 |
| SwarmEnemy.obj | 横方向へ泳ぐ小魚ドローン | 112 | 3 | 0.957 |
| PaintShooterEnemy.obj | 紫のタンクを持つ散布兵器 | 700 | 5 | 2.64 |

MTLは同名のOBJと並び、`textures/` の共有64×64画像5枚を相対参照する。通常敵・移動敵・装甲敵・ペイント敵の既存半径3、群れの半径1.15に収まるサイズで出力。ゲームの移動、HP、攻撃、判定、既存スケールには変更を加えていない。

`EnemyAppearanceTable.h` のSTAGE1行は `*_Body.obj` を指定し、`EnemyAppearanceParts.h` の対応表から残りのパーツを追加する。通常敵4、滑空敵5、装甲敵5、群れ2、ペイント敵6の計22モデル。STAGE03の氷モデル・他ステージ・チュートリアルの外見は維持。分割モデルはSTAGE1開始時に読み込み、同じモデルと画像のGPUデータを共有する。群れのフェードは全パーツへ反映する。

専用PS `resources/Shaders/Object3D/RuinsEnemy/Render.PS.hlsl` は、回転装置と同じ材質区分を使う。UVのU座標の整数帯で材質を識別する：0〜1＝石、2〜3＝金属、4〜5＝橙の目、6〜7＝青緑の結晶、8〜9＝紫のタンク・噴口。編集時はこの区分を維持する。OBJを一般のビューアーで開くだけではゲーム用の発光PSは適用されない。

生成元：`project/Tools/ModelGeneration/CreateRuinsEnemies.py`。編集用：`ruins_enemies.blend`。参考画像：`previews/ruins_enemies.png`。プレビュー用の位置・大きさ・ライトはOBJに含めない。プレビューはBlenderによる参考表示で、ゲームのスクリーンショットではない。

編集用Blendには `敵名_Parts` コレクションで分割オブジェクトも保存している。参考画像で二重描画しないよう非表示にしているので、編集したい敵のコレクション内のオブジェクトを表示して使用する。接合した `敵名.obj` は交換・参考用として残しており、実行時には読み込まない。

動作は `EnemyAppearanceMotion.h` と `BaseEnemy::UpdateAppearanceParts` で設定する。本体の上下動、黒目のプレイヤー追従、左右の足・爪・翼の交互移動、尾の振動、タンクの上下動、発射時の砲口後退を各パーツのTranslateへ加算。目の枠と橙色の発光部は本体に固定し、`Eye` パーツには黒目だけを持たせる。黒目の寸法に合わせた移動幅と視線の強調倍率を使い、プレイヤーを見ていることを読み取りやすくしている。パーツ自体の回転・スケールのアニメーションは使わず、親の既存の向き・スケールを継承する。物理位置・移動ロジックは変更せず、当たり判定は元の位置に残す。分割による三角形の増加はないが、パーツ数に応じて座標更新・描画回数・定数バッファが増える。

足・爪・翼の希望振幅は横0.09・縦0.14、尾は0.18、タンクは0.07のモデル単位。従来から約2〜3倍に強めた。各パーツの頂点の最大半径、親スケール、既存の当たり判定半径からTranslateの上限を初期化時に計算し、本体の上下動と合わせても判定からはみ出さない範囲へ制限する。動作はdeltaTimeで進み、プレイヤー追従は補間し、敵ごとに位相を変える。発射の反動は既存の弾追加時に通知し、攻撃周期や弾道は変更しない。

`project/Tests/RuinsEnemyAssetTests.cpp` はSTAGE1/03の対応、他ステージへの非適用、分割モデルの三角形合計、各パーツの半径と上限を含む60秒分の動作範囲、黒目の追従方向と上限、砲口の後退方向、群れの三角形数、テクスチャ参照を検査する。ゲーム内の見た目・向き・発光・動作は実行環境での確認が必要。
